# Vivo Live Photo 界面重构设计（v1.3.0）

日期：2026-10-09
状态：已确认
范围：`app/src/main/java/com/vliveconvert/app/ui/`、`MainActivity.kt`、`app/src/main/res/values/strings.xml`

## 背景与问题

主界面把全部控件平铺：顶栏 4 个纯文字按钮（日志 / 修复时间 / 移到相机 / 清空），底部输出目录行
+ 2 个带两行说明的开关 + 2 个按钮。照片列表被压缩到约 90px（屏幕高度约 1/7），
而这些都是低频操作——工具的日常路径只有「选照片 → 开始转换」。

代码审查发现的其它问题：

| # | 问题 | 位置 |
| --- | --- | --- |
| 1 | 顶栏 4 个纯文字按钮，热区小、窄屏拥挤、无图标 | `MainScreen.kt` 顶栏 |
| 2 | 品牌名三处不一致：权限页「VLiveConvert」、主页「Vivo Live Photo」、`app_name` 第三种 | `PermissionScreen.kt:39`、`MainScreen.kt:92`、`strings.xml` |
| 3 | 列表项状态仅靠文字颜色区分，无图标/徽标；失败原因长文案换行挤压行高 | `MainScreen.kt` `ConvertItemRow` |
| 4 | 排版层级几乎全为 Material 默认值（`Typography` 只覆写 `bodyLarge`，且其值等于默认值） | `ui/theme/Type.kt` |
| 5 | 「源文件无 GPS」的行内重转入口缺失，用户需滚回顶部横幅 | `MainScreen.kt` |

## 设计决策

采用「顶栏收口」方案（候选方案中的 B）。**不采用**把主界面改成相册网格的抽屉方案——
`PickerScreen` 已是相册网格，主界面再网格化会与之职责重复、用户难以区分两个页面。

核心原则：主界面只保留主路径；状态用「图标 + 颜色 + 徽标」三重编码。

## 具体改动

### 1. 主界面（`MainScreen.kt`）

- **顶栏**：标题 + 副标题（左）、⚙ 圆形 tonal 按钮（右）。移除 4 个文字按钮。
- **列表头**：`已选 N 张` + `清空`（仅列表非空时显示）。
- **状态条**：折叠为单行摘要（如 `成功 3 · 失败 0`）+ `查看详情 ›`，点击弹 `AlertDialog`
  显示完整文案（GPS 警告等长文案不再占据多行）。
- **底部**：设置摘要一行（`输出 DCIM/Camera · 删原图 关` + `设置 ›`）+ 两个主按钮
  `＋ 添加` / `开始转换（N）`。
- **转换中**：整体进度条 + `已处理 n/N · 百分比` + `取消转换`；列表项显示不定长进度条。
- 保留块：位置权限警告横幅、重新转换横幅、恢复原图入口（均为可操作、时效性内容）。

### 2. 列表项（`ConvertItemRow`）

缩略图右下角叠加状态角标，状态文案前置图标，失败/无位置行用底色区分：

| 状态 | 角标 | 文案 |
| --- | --- | --- |
| 完成且有位置 | 绿 ✓ | `📍 完成 · 位置已保留` |
| 完成但无位置 | 琥珀 ! | `⚠ 完成 · 无位置信息` + 行内「重转」按钮 |
| 转换中 | — | `◐ 转换中` + 不定长进度条 |
| 失败 | 红 ✕ | `✕ 失败 · 原因`（行底色 `errorContainer`） |
| 待转换 | — | `○ 待转换` |

行内「重转」与顶部横幅共用同一套重转流程（含位置权限门禁）。
失败原因过长时行内截断为 1 行，完整原因在「查看详情」中查看。

**相对设计稿的一处调整**：设计稿中单项进度显示为百分比，实际实现改为**不定长进度条**——
转换是对单个文件的字节级处理（`Converter.convertToVivoSingle` 无粒度进度回调），
显示具体百分比会是伪造数据。不定长动画是诚实的表达。

### 3. 设置页（新增 `ui/SettingsScreen.kt`）

收纳全部低频项：输出目录（点击弹窗修改）、`移到相机相册` 开关、`删除原图` 开关、
`修复文件时间`、`把输出移到相机相册`、`导出崩溃日志`（仅有崩溃时显示）、版本信息。

### 4. 排版（`ui/theme/Type.kt`）

建立明确层级，中文行高放宽至约 1.5 倍；移除 `bodyLarge` 上多余的 `letterSpacing`（其值等于默认值）。

| 样式 | 规格 |
| --- | --- |
| headlineSmall | 24sp / W700 / -0.3sp |
| titleLarge | 18sp / W700 / -0.2sp |
| titleMedium | 15sp / W600 |
| bodyMedium | 14sp / 21sp |
| bodySmall | 13sp / 19sp |
| labelLarge | 14sp / W600 |
| labelMedium | 12sp / W500 / 0.1sp |
| labelSmall | 11sp / W500 / 0.2sp |

### 5. 品牌统一

应用内显示统一为 `Vivo Live Photo`（新增 `app_display_name` 字符串资源）。
**桌面图标名 `Vivo Live Photo yuting改进版` 保持不变**——用于与原版 `brovast/VLiveConvert` 区分。

## 影响与风险

- 纯 UI 层改动，不触碰 `core/`（字节级转换管道）与 `service/` 的转换语义。
- `MainActivity` 需新增 `Screen.Settings` 分支与状态；现有转换/权限/重转流程的**行为不变**，
  仅入口位置从顶栏文字按钮改为设置页条目。
- 回归验证：现有 28 个 JVM 单测必须全绿；`assembleRelease` 构建通过。

## 验收

1. 主界面列表可视区域显著增大（约 90px → 约 300px，视屏幕而定）。
2. 顶栏仅剩标题 + ⚙；底部仅剩设置摘要 + 两个主按钮。
3. 每种状态在列表项上都有图标/徽标区分，不依赖单一颜色。
4. 「完成 · 无位置信息」的条目行内可直接重转。
5. 全应用品牌名为 `Vivo Live Photo`。
6. 单测全绿、release 构建成功。
